# 知识树中的教程与复习题：融合式引入设计

## 1. 结论

知识卡片和复习题不应成为左侧新页面，也不需要依赖错题卡片跳转。推荐把它们放进知识树右侧的当前内容区：

```text
知识树选择
  → 关联错题
  → 知识卡片
  → 复习题
```

三种内容通过页内标签切换。知识卡片是一知识点一张，可在全部、学科、章节或知识点范围内检索；进入具体卡片后，它与复习题共享同一批来源错题和同一条分类路径。

本次实现仅修改 `docs/knowledge-tree-*` 隔离 demo，没有修改 React、Tauri、数据库或 release 代码。

## 2. Demo 入口

直接打开：

```text
docs/demo/knowledge-tree/index.html
```

推荐体验顺序：

1. 查看默认选中的“一元二次不等式”，它由 3 道错题共同更新。
2. 在右侧切换“关联错题 / 知识卡片 / 复习题”。
3. 点击“数学 / 函数”章节，在知识卡片标签下查看该章节的 3 张卡片。
4. 在复习题中查看答案并标记掌握。

demo 使用内置数据，不读取数据库、不调用 AI，也不会修改错题。

## 3. 为什么这样更统一

知识树本身已经回答了三个关键问题：

- 学什么：当前选中的三级知识点。
- 为什么学：该节点下已经积累的错题。
- 用什么学：从这些错题持续更新的知识卡片和针对性复习题。

因此“知识卡片”和“复习题”更适合作为知识树的内容视图，而不是全局导航。左侧只保留稳定的产品一级能力，例如“我的错题”和“新增错题”。

错题也不新增跳转按钮。来源错题在知识卡片和复习题底部以内联折叠区展示，用户可核对依据但不会被带离当前学习上下文。

## 4. 层级交互规则

### 选择学科或章节

- 展示该节点下聚合后的错题。
- “知识卡片”展示该范围内的一组知识卡片，可继续通过树缩小范围。
- “复习题”置灰，并提示用户继续选择具体知识点。

学科或章节适合作为知识卡片检索范围，但不适合作为一次复习的目标，否则会混合多个知识点和难度。

### 选择三级知识点

- 默认打开该知识点的知识卡片。
- 解锁“复习题”。
- 切换视图时不折叠知识树、不清空当前路径。
- 改选另一个三级知识点时，右侧原位更新并清空上一知识点的答题状态。

### 清除选择

- 回到全部错题。
- “知识卡片”展示全部知识卡片。
- 仅“复习题”恢复置灰。

## 5. 内容结构

每个知识点对应一张知识卡片。知识卡片包含：

- 来源错题数、错误样本数和证据状态。
- 三个可检验的学习目标。
- 核心认识。
- 解题路径。
- 从全部同知识点错题聚合的错误模式。
- 可展开的来源错题列表。

复习题包含：

- 1 道变式迁移题：检查方法能否迁移。
- 最多 2 道来自不同错题的原题复练：避免只复习第一道题。
- 1 道综合错因归纳：检查能否跨题识别共同漏洞。
- 答案和解析的主动揭示。
- “已掌握”自评与组内进度。
- 同一批来源错题列表。

## 6. 正式代码边界

正式落地时不把教程或复习题字段塞进 `Card`。推荐结构：

```text
CardsPage
  ├─ KnowledgeTreeFilter
  └─ KnowledgeContextView
       ├─ RelatedCardsView
       ├─ KnowledgeCardList
       ├─ KnowledgeCardDetail
       └─ ReviewView

LearningGenerationService
  ├─ updateKnowledgeCard(request)
  └─ generateReviewSet(request)
         ↓
Tauri command / AI provider manager
```

`KnowledgeContextView` 只管理右侧视图和临时答题状态。生成服务只读不可变错题快照，不持有写卡片权限。

## 7. 建议生成合约

```ts
type LearningGenerationRequest = {
  mode: "tutorial" | "review";
  topic: { subject: string; chapter: string; name: string };
  sourceCards: CardSnapshot[];
  options: { difficulty?: "basic" | "medium" | "hard"; questionCount?: number };
};

type GeneratedDraft = {
  runId: string;
  promptVersion: string;
  sourceRevisions: Array<{ cardId: string; revision: number }>;
  knowledgeCard?: KnowledgeCardDraft;
  reviewSet?: ReviewQuestionDraft[];
  warnings: string[];
};
```

请求冻结 `cardId + revision`。输出中的段落和题目应保留 `sourceCardIds`，方便用户在当前区域核对来源。

## 8. AI 接入

复用现有 AI Provider 管理层，但新增独立命令和 Schema，不复用“整理错题”的 prompt：

- `generate_or_update_knowledge_card`
- `generate_review_set`
- `knowledge-card-draft.schema.json`
- `review-set.schema.json`

普通自动化测试使用固定 fixture，不调用真实模型。AI 失败、超时或未连接时，右侧保留当前知识点和错题视图，并允许重试；任何生成结果都不能自动改写来源错题。

## 9. 分阶段落地

### A. 当前融合 demo

验证树节点选择、三视图切换、来源展开、答案揭示和掌握标记。

### B. 只读接入真实错题

把右侧视图接到真实 `KnowledgeSelection` 和卡片快照，仍使用确定性 fixture，验证空状态和来源 revision。

### C. 接入 AI 草稿

增加两个 Tauri command、两个 Schema、固定合约测试和可审阅结果。知识卡片按知识点稳定标识更新，复习题只存在于当前练习上下文。

### D. 再评估持久化

只有实际使用证明需要历史教程或间隔复习时，再增加独立的学习资料与练习记录表。不要提前引入知识图谱、向量库或完整学习管理系统。
