## 记录状态

每项功能使用以下证据等级：

- `代码确认`：已从当前挂载代码或服务实现确认。
- `测试覆盖`：存在直接对应的自动化测试。
- `人工待验`：需要运行应用，观察真实视觉、焦点、窗口尺寸或操作反馈。
- `桌面待验`：必须在 Tauri 桌面程序验证，浏览器预览不能替代。

迁移状态统一使用：

`待设计 → 已映射 → 已实现 → 已验证`

如果决定不迁移某项功能，必须记录为 `明确废弃`，并附决策理由、影响范围和批准人；不得直接删除清单行。

## 完成闸门

旧 UI 只能在以下条件同时满足后移除：

1. 所有 P0、P1 功能均已映射，且不存在“入口待定”。
2. 所有行为契约均标记为“保持”或有明确批准的变更记录。
3. P0 用户旅程在新 UI 中完整走通。
4. 加载、空数据、错误、冲突、取消和成功状态均有对应设计。
5. 代码改动完成后按 `AGENTS.md` 执行与范围对应的验证；前端改动至少运行 `pnpm check`。
6. 自动化测试结果和人工截图或录屏证据已经登记。
