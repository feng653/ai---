# 现有用户旅程

用户旅程用于验证完整任务，而不仅是单个控件。每条旅程都要在旧 UI 补充一次证据，并在新 UI 实现后重复同样验收。

## J-01：手动创建一张错题卡片（P0）

主流程：

1. 从侧栏、顶栏或空状态进入“新增错题”。
2. 输入题目，或选择/拖入题目图片。
3. 如有图片，旋转或裁剪后确认使用。
4. 填写答案、解法、错因和错误类型。
5. 添加最多 3 个知识点。
6. 点击“保存卡片”。
7. 进入详情页，核对字段、图片、状态和更新时间。
8. 返回错题库，在知识树和卡片列表中找到新卡片。

关键分支：仅文字、仅图片、完全空白、图片超限、图片导入失败、知识点达到上限、保存失败。

覆盖功能：`NAV-001`、`CARD-003`～`CARD-005`、`IMAGE-001`～`IMAGE-004`、`LIB-001`、`TREE-001`。

当前证据：代码和部分单元测试确认；完整录屏待采集。

## J-02：编辑、暂存并解决版本冲突（P0）

主流程：

1. 从错题库打开已有卡片。
2. 进入编辑器并修改内容。
3. 等待自动草稿写入后，不正式保存直接返回。
4. 取消离开提示，确认仍停留且内容未丢失。
5. 再次返回并确认离开，然后重新进入编辑器。
6. 确认草稿恢复。
7. 正式保存，进入详情页并确认 revision 增加。

冲突流程：用两个上下文编辑同一卡片；第一个保存后，第二个保存必须失败且不得覆盖。

覆盖功能：`CARD-001`、`CARD-006`～`CARD-008`、`CONTENT-001`。

当前证据：revision 有自动测试；草稿、离开提示和完整冲突体验待人工走查。

## J-03：使用 AI 整理并选择性接受建议（P0）

主流程：

1. 新建或编辑一张含题目文字/图片的卡片。
2. 点击“AI 整理”；未连接时完成连接或看到不可用错误。
3. 观察当前请求进度。
4. 审阅 warnings、不确定字段和建议内容。
5. 在建议生成后继续修改一个字段，观察冲突标识。
6. 只选择部分建议并点击“接受所选”。
7. 确认建议进入表单，但详情中的持久化卡片尚未改变。
8. 点击“保存卡片”，再到详情核对最终内容。

关键分支：无输入阻止、连接失败、AI 失败、拒绝全部、零字段选中、请求进度隔离。

覆盖功能：`AIORG-001`～`AIORG-004`、`CARD-006`～`CARD-008`。

当前证据：建议选择和事件过滤有自动测试；真实 Provider 流程待桌面验收。

## J-04：从知识树学习并复习（P1）

主流程：

1. 在知识树搜索并选择一个具体知识点。
2. 在“关联错题”查看筛选结果。
3. 切换到“知识卡片”，查看核心方法、易错提醒和来源证据。
4. 打开一张来源错题，再返回知识空间。
5. 切换到“复习题”，选择一个或多个知识点范围。
6. 在范围内继续勾选作为生成依据的具体错题。
7. 选择生成总数；下限等于所选错题数，保证每道来源题至少生成 1 张。
8. 执行“生成并保存”，查看生成进度和保存结果。
9. 在习题卡片列表查看答案、知识点与来源错题，并可继续生成。

关键分支：未选知识点、知识点无关联错题、来源错题全部取消、数量下限联动、AI 失败、部分题生成失败、来源 revision 变化、保存失败。

覆盖功能：`TREE-001`～`TREE-003`、`LIB-004`、`KNOW-001`～`KNOW-004`、`REVIEW-001`～`REVIEW-003`。

当前证据：派生逻辑和主要切换有自动测试；导航上下文与视觉状态待人工走查。

## J-05：配置并切换 AI 服务（P0）

Codex 流程：

1. 进入“AI 接入”，选择 Codex。
2. 通过浏览器登录并返回应用。
3. 确认已登录/当前使用状态。
4. 如非当前服务，设为当前。
5. 重新登录或经确认退出。

API 流程：

1. 选择 DeepSeek，或新增一个独立自定义 API。
2. 填写名称、Key、Base URL 和模型。
3. 显示/隐藏本次输入的 Key。
4. 测试连接。
5. 保存并确认成为当前服务。
6. 再次进入，确认 Key 不回显；留空保存仍保留原 Key。
7. 切换服务，或经确认删除配置。

关键分支：配置读取失败、登录取消/失败、测试失败、保存失败、删除失败、操作中重复点击。

覆盖功能：`AICONN-001`～`AICONN-004`、`AGENT-013`。

当前证据：前端调用参数有自动测试；凭据与真实登录必须在桌面验收。

## J-06：Agent 读取并经批准写入卡片（P0）

主流程：

1. 打开 Agent，确认当前运行时标识、模式、思考强度和工具权限。
2. 输入文字、使用快捷建议，或通过 `@` 引用卡片。
3. 可附加/拖入图片，使用 Enter 发送。
4. 查看决策摘要、只读工具开始与完成状态。
5. 对只读问题直接获得回答。
6. 发起创建、修改或删除任务。
7. 在审批卡查看工具名称、目标和影响。
8. 分别验证拒绝不改数据、批准后数据变化并刷新列表。

关键分支：仅聊天模式、图片超限、运行错误、没有搜索结果、停止本轮、达到步骤上限、批准处理失败。

覆盖功能：`AGENT-001`～`AGENT-010`、`AGENT-012`、`AGENT-013`。

当前证据：控制项和 reducer 状态有自动测试；真实工具执行必须在桌面验收。

## J-07：手动开始 Agent 新对话（P0）

主流程：

1. 在已有历史的 Agent 中发送“创建新对话”。
2. 确认系统只提示必须使用标题栏按钮，历史不被清空。
3. 发起一个活动 run，再点击标题栏“新对话”。
4. 确认活动 run 被取消，时间线重置为欢迎消息。
5. 发起一个需要写审批的任务，不处理审批，点击“新对话”。
6. 确认待审批操作被拒绝，数据没有变化。

覆盖功能：`AGENT-010`、`AGENT-011`。

当前证据：静态代码确认；活动 run、待审批和临时图片的清理结果必须桌面验收。
