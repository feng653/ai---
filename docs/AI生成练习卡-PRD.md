12. 所有 AI 生成功能统一从全局浮动 Agent 发起；页面不再自行持有独立 AI 生成流程。
13. 产品保持“一个 Agent”，不拆成多个用户可见或递归协作的子 Agent；复杂任务由有边界的工具步骤完成。
14. Agent 通过多轮对话理解目标、补齐信息、展示任务计划、请求必要审批、执行工具并汇报结果。
15. Agent 对话、任务检查点、待处理结果和运行状态需要跨页面与收起状态保留。

## 1. 执行摘要

知拾将为大学阶段学习者和成人自学者提供一个**统一的浮动 AI Agent**。所有 AI 生成任务——错题整理、灵活知识卡生成与编辑、知识驱动练习生成——都在同一对话窗口中发起。用户用自然语言说明目标，Agent 通过多轮对话读取必要上下文、询问缺失信息、形成任务计划，并调用有边界的工具完成工作。

练习生成仍由用户选择的知识卡驱动，错题作为可选的个人错误证据；校验成功后按批次自动保存。该能力解决的不是“缺少考试真题”，而是通用题库难以覆盖个人知识笔记中的细节和真实薄弱点。V1 以生成题是否真实训练所选知识细节作为首要质量标准，同时要求 Agent 保持本地优先、上下文有边界、写入需审批、来源可追溯、多轮状态可恢复和运行可观察。

## 2. 问题陈述

### 2.1 谁遇到了这个问题

主要用户是需要自主组织学习材料的大学生和成人自学者。他们可能学习高等数学、专业课程、资格考试或其他需要理解与练习结合的内容，并已经通过错题或零散笔记记录个人薄弱点。

### 2.2 问题是什么

用户能够记录知识内容或错题，但很难快速获得**针对自己记录的具体知识细节**的新练习：

- 公共题库和考试真题面向通用大纲，未必覆盖用户刚记录的概念边界、推导步骤、易混点或个人理解。
- 手工搜索、筛选和改编题目成本高，且很难保证题目与目标细节真正对应。
- 反复查看笔记或重做原题容易产生“看懂了就是掌握了”的错觉，缺少新的题面来验证迁移。
- 当前 AI 能力分散在错题编辑器、知识卡页面、复习题页面和浮动 Agent 中。用户需要理解不同入口、不同保存语义和不同失败恢复方式，Agent 也无法在同一任务中连续完成“找材料—生成知识卡—再生成练习”。

### 2.3 为什么痛苦

- **用户影响**：知识记录与实际练习脱节；用户知道自己需要强化什么，却无法低成本地把细节转化为可作答的新题。
- **产品影响**：知拾已经覆盖“记录错题—沉淀知识—生成复习题”的路径，但现有知识卡模型、分散的 AI 入口和彼此隔离的运行状态限制了这条路径的连续性。

### 2.4 当前证据

已通过仓库静态盘点确认：

- 产品定位是本地优先的个人错题卡片桌面应用，见 [`../README.md`](../README.md)。
- 当前练习生成支持知识点、来源错题、相对难度、数量和补充要求，成功后自动保存，见 [`功能使用流程.md`](./功能使用流程.md) 和 `src/features/cards/ReviewBuilder.tsx`。
- 当前持久化知识卡以知识点 `key` 为主键，一个知识点只能保存一条记录；内容固定为“核心方法”和“易错提醒”，见 `src-tauri/migrations/003_knowledge_cards.sql` 与 `src-tauri/src/domain/knowledge.rs`。
- 当前流程没有生成预览、逐题筛选或批次撤销；这是已记录的后续决策点，见 [`功能使用流程.md`](./功能使用流程.md)。
- 当前界面维护来源错题勾选状态，但请求构建仍按所选知识点重新收集来源，存在“用户勾选”与“实际请求来源”不一致的实现风险。
- 当前浮动 Agent 已挂载在全局应用壳中，具备多轮消息、只读工具、写操作审批、停止本轮和工具事件时间线；但工具仅覆盖错题搜索/读取/增删改与知识点搜索，尚不能读写灵活知识卡、管理提示词模板或生成练习批次。
- 当前 Agent 只传递最近消息字符串，前端时间线和后端待审批状态主要保存在内存中；刷新或重启后不能可靠恢复会话、任务检查点或审批。

🔶 **假设**：目标用户普遍已经有值得转化为练习的个人知识笔记。现阶段没有用户访谈或使用数据证明该问题的发生频率。

🔵 **开放问题**：目前有多少用户会主动记录知识细节，以及他们最常记录哪些内容类型？

## 3. 目标用户与待完成任务

### 3.1 主要用户画像

- **角色**：大学生、成人自学者、资格考试备考者或需要持续学习专业知识的个人用户。
- **环境**：个人桌面设备、本地资料为主；学习时间碎片化，不一定有教师或题库服务协助。
- **目标**：把刚理解、容易混淆或曾经做错的知识细节转化为可检验的练习。
- **痛点**：现成练习不够个性化；手工出题成本高；笔记与练习分散。
- **当前行为**：记录错题或笔记，搜索近似题，重复阅读解析，或直接重做原题。

🔶 **假设**：V1 不区分不同学科的角色和权限，所有内容均属于单一设备上的个人用户。

### 3.2 次要用户

🔶 **假设**：中学生也可能使用此能力，但 V1 不以校内作业、教师布置或家长监督为设计中心。

### 3.3 Jobs-to-Be-Done

- **功能任务**：当我记录了一个知识细节或发现一个薄弱点时，我希望快速生成只针对这些内容的新题，以便立即练习。
- **情绪任务**：我希望确认自己不是“只是看懂了”，而是真的能在新题面中使用这个知识。
- **社会任务**：不是 V1 的主要驱动；本地个人学习不依赖分享、排名或教师审核。

## 4. 战略背景

### 4.1 产品目标

本项目当前主链路是：

```text
记录错题 → 整理错因 → 沉淀知识 → 生成复习题 → 再次练习
```

本需求同时补强两层能力：

1. 让知识内容不再只是按知识点聚合展示，而能直接成为可选择、可追溯的练习生成依据。
2. 把分散在不同页面的 AI 生成功能收口到一个浮动 Agent，使 Agent 能在同一多轮任务中完成资料检索、澄清、计划、生成、审批和结果汇报。

### 4.2 为什么现在做

- 现有代码已经具备 AI Provider、结构化输出、来源 revision 校验、后台运行和练习卡持久化能力，继续收敛的技术基础已经存在。
- 当前“一知识点一张固定结构卡”的数据模型与大学/成人学习中细粒度、连续积累的笔记需求不匹配。
- 当前生成逻辑仍以来源错题为强制中心，与“强化知识掌握度”的产品目标不完全一致。
- 当前浮动 Agent 已有工具循环、事件时间线和审批骨架，但缺少知识卡与练习生成工具，无法承接全部 AI 工作。
- 当前各页面自己管理生成状态和上下文，会形成多套入口、提示、生命周期和失败恢复逻辑；继续扩展会放大不一致。

### 4.3 市场与竞争

本 PRD 不做 TAM/SAM/SOM 或竞品结论。🔵 **开放问题**：如该功能进入对外商业化评审，需要补充题库、笔记与 AI 学习工具的竞品证据。

### 4.4 商业影响

🔵 **开放问题**：项目当前没有提供收入、留存或付费目标。本 PRD 只定义用户价值与产品质量指标，不虚构商业目标。

## 5. 解决方案概述

### 5.1 统一浮动 Agent 入口

- 右下角“AI Agent”是所有 AI 生成功能的唯一执行入口，保持挂载在全局应用壳中，不新增独立一级导航。
- 错题编辑器、知识卡片和复习题页面可以保留“让 Agent 整理”“让 Agent 生成知识卡”“让 Agent 生成练习”等上下文入口，但点击后只负责打开浮动 Agent、附加当前上下文胶囊并预填任务意图；页面自身不直接调用模型或持有生成任务。
- 上下文入口不得在用户未发送或确认任务时静默调用模型、修改内容或开始收费操作。
- 手动创建、编辑、保存和删除知识卡/错题仍保留在原页面；统一的是 AI 工作流，不是所有手动操作。
- Agent 收起时，页面继续可用；浮动按钮展示运行中、等待用户和等待审批的状态徽标。
- 浏览器预览只模拟交互，不执行真实 Agent、AI Provider 或写工具；桌面端结果单独验收。

### 5.2 一个 Agent、多个有边界任务

V1 不引入多个子 Agent。一个面向用户的 Agent 根据意图选择独立工具和结果协议：

| 任务 | Agent 工作方式 | 持久化边界 |
|---|---|---|
| 普通学习对话 | 使用轻量对话协议回答，不加载整库卡片 | 不写卡片 |
| 整理错题 | 读取被引用错题或附件，生成逐字段提案，可多轮修订 | 用户确认选定字段后才保存 |
| 生成/编辑知识卡 | 读取所选材料，生成一张或多张灵活知识卡提案，可拆分、合并或改写 | 每张卡独立确认；更新时校验 `expectedRevision` |
| 生成练习卡 | 澄清知识卡、可选错题、数量、难度和提示词，形成批次计划 | 用户批准批次计划后生成；校验成功自动保存整批 |
| 删除练习 | 读取批次和勾选范围，展示删除影响 | 批量删除和删除本批均需批准 |

每类任务使用独立 Prompt、Schema、解析器和校验器，不把所有结果继续塞进一个万能卡片 Schema。Agent 负责协调工具，不绕过领域服务直接访问数据库、文件系统、凭据或网络。

### 5.3 多轮任务拓扑

```text
用户说明目标或从页面唤起 Agent
  → Agent 识别任务类型与完成条件
  → 按需检索卡片、知识点和提示词模板
  → 只追问真正缺失的信息
  → 展示可核对的任务计划
  → 用户修订计划或批准下一步
  → Agent 调用专用生成工具
  → 领域层执行结构、来源和 revision 校验
  → 执行需要批准的保存/删除工具
  → Agent 汇报结果、失败项和下一步
```

- Agent 一次只推进一个主要任务；用户提出无关目标时，Agent 应请求完成、暂停或放弃当前任务，避免上下文串线。
- 多轮中的用户决策被写入结构化任务状态，例如来源、数量、难度、模板、已确认约束和待解决问题，而不是只依赖聊天文本重读。
- 用户可以在执行前说“只用第 2、3 张知识卡”“把第 1 张拆成两张”“难度改为更难”等；Agent 更新同一任务计划，不新建重复任务。
- 新提案替代旧提案时，旧提案标记为 `superseded`，不能继续批准。
- 用户拒绝写操作后，Agent 保留对话和任务目标，允许继续讨论或生成修订版；拒绝本身不等于清空会话。

### 5.4 上下文架构

Agent 按“始终保留、短期工作、按需检索、明确排除”四层装配上下文：

| 层级 | 内容 | 规则 |
|---|---|---|
| 始终保留 | 产品安全边界、写入审批规则、字段定义、当前 Provider 能力 | 高密度、版本化，不随聊天无限增长 |
| 短期工作上下文 | 当前任务目标、已确认参数、未决问题、对话摘要、最近相关消息 | 每轮更新结构化摘要；完成或放弃任务后归档 |
| 页面上下文胶囊 | 当前路由、卡片 ID、知识点选择、当前标签、用户明确勾选的对象 ID | 只传标识和必要摘要；正文按需读取 |
| 按需检索 | 指定错题/知识卡的当前版本、提示词模板、相关批次 | 通过只读工具获取；每次限制数量并记录来源 |
| 明确排除 | 全部卡片库、无关历史、未选卡片、凭据、系统密钥、完整旧对话 | 不因“可能有用”而加入上下文 |

- 每个检索结果都带稳定 ID、revision、用途和来源；Agent 必须能说明“为什么需要这段上下文”。
- 生成获得批准后冻结所选来源快照；批准前来源变化时，计划失效并要求重新核对。
- 长对话采用“结构化任务状态 + 高密度摘要 + 最近消息”，不得把全部历史反复发送给模型。
- 不在前端聊天历史中存放 API Key、Codex 凭据、原始系统提示词或未授权的本地文件内容。

### 5.5 对话、任务与运行持久化

- 对话消息、结构化任务、任务检查点、提案、审批状态、工具调用摘要和最终产物均持久化到本地存储。
- 收起 Agent 或在应用内切换页面不会丢失对话、运行状态、结果或待审批项。
- 同一会话内的下一轮可以引用上一轮已确认的目标和产物，不要求用户重新描述整个任务。
- 应用进程仍存活时，已批准的后台生成可以继续；浮动按钮与时间线持续显示状态。
- 应用关闭或异常退出时，不宣称模型调用仍在后台运行。重新打开后，原 `running` 状态必须变为 `interrupted`，用户可以从最近安全检查点恢复或放弃。
- 待审批项在重启后可以恢复展示，但执行前必须重新校验来源 revision、提案状态和影响范围；不得自动批准。
- “新对话”会先处理活动任务和待审批项：用户确认后取消活动运行、拒绝或归档待审批项，再创建新会话。
- V1 每个会话最多一个活动运行；不设计并行运行队列或 Agent 间委派。

### 5.6 工具与审批矩阵

| 工具类别 | 示例能力 | 默认行为 |
|---|---|---|
| 只读检索 | 搜索/读取错题、知识卡、知识点、提示词模板、练习批次 | Agent 可自动调用，时间线必须可见 |
| 内容生成 | 生成错题字段提案、知识卡提案、练习批次候选 | 只能返回类型化产物，不能直接写数据库 |
| 创建/更新 | 保存错题字段、创建/更新知识卡、保存练习批次、保存模板 | 执行前展示对象、数量、字段和影响并请求批准 |
| 删除 | 删除知识卡、选中练习、整个练习批次、提示词模板 | 始终请求批准；显示准确数量与级联影响 |

审批粒度：

- 错题提案按卡片与字段确认，不能静默覆盖用户内容。
- 多张知识卡提案保持每张卡独立，可逐张选择和确认；被拒绝的卡不保存。
- 练习卡在开始生成前审批批次计划，审批卡必须显示知识卡、可选错题、生成数量、难度、模板和“成功后自动入库”。批准后生成与事务保存作为同一受控工具任务完成，不逐题重复审批。
- 批量删除与删除本批在执行前再次审批，不复用生成时的批准。
- 所有更新和删除在执行时重新校验 `expectedRevision`；审批过期、来源变化或提案被替代时拒绝执行。

### 5.7 总体业务流程

```text
从任意页面打开浮动 Agent
  → 描述目标或接收页面预填意图
  → Agent 多轮补齐知识卡、可选错题、难度、数量和提示词
  → 用户核对并批准批次计划
  → Agent 调用练习生成工具
  → 结构、覆盖、来源和 revision 校验
  → 校验成功后自动保存为独立练习卡
  → Agent 汇报批次并提供打开、继续生成或清理入口
```

### 5.8 灵活知识卡

- 同一知识点下允许存在多张知识卡，不再使用知识点路径作为知识卡唯一主键。
- 每张卡必填标题与自由正文；正文支持现有数学内容渲染能力，包括 Markdown/LaTeX。
- 卡片可选使用内置类型：定义、定理、推导、例子、易错点、个人理解；未选择时显示为“未分类”。
- 用户可以创建、重命名和删除个人自定义类型，例如“公式清单”或“证明技巧”。
- 类型只用于组织与筛选，不改变正文结构，也不限制用户写法。
- 用户可以手动创建、编辑和删除知识卡；AI 生成知识内容仍是增强能力，不是创建知识卡的前提。
- 每次编辑增加 revision；练习卡记录生成时使用的知识卡 ID 与 revision。

🔶 **假设**：V1 每张知识卡至少关联一个知识点，并最多关联三个知识点，以延续现有知识点数量约束。

### 5.9 知识驱动的来源选择

- 发起生成时至少选择一张知识卡。
- 错题是可选来源，用来补充真实作答、错误位置、错误原因和错误类型。
- AI 只能使用用户本次明确选择的知识卡和错题；不能把同知识点下未勾选的卡片自动加入请求。
- 每张所选知识卡至少对应一道生成练习，生成数量下限等于所选知识卡数。
- Agent 的批次计划在批准前显示知识点、知识卡、错题、难度、数量和提示词摘要。
- 每张生成题必须声明其训练重点以及引用的知识卡；引用错题时同时记录错题来源。

🔶 **假设**：V1 一批生成仅允许选择同一学科下的知识卡，避免跨学科题目语义和输出结构不稳定。

### 5.10 提示词模板

- 用户可以创建、命名、编辑、选择和删除个人提示词模板。
- 模板示例：“生成证明题”“增加反例辨析”“侧重概念边界”“先问结论再要求推导”。
- 选择模板后，用户仍可填写仅用于本次生成的补充要求。
- 提交给模型的是“产品固定规则 + 模板内容 + 单次补充要求”；界面应让用户看清本次启用了哪个模板和补充要求。
- 模板与单次补充均被视为不可信输入，不能覆盖知识范围、数量、来源、完整性、安全或结构化输出规则。
- V1 沿用当前 500 字符的附加要求上限；模板与单次补充合并后的最终限制需在技术评审时确认。
- 不允许用户编辑系统提示词、工具权限或 JSON Schema。

### 5.11 生成、校验与保存

- 保留“批准批次计划后，生成成功即自动保存”的 V1 心智，不增加逐题预览与确认步骤。
- 生成在 Agent 后台任务中运行；用户收起 Agent 或离开当前页面后，返回仍能看到运行、失败或完成状态。
- 离开应用后任务继续运行不属于 V1 保证；重启后按 `interrupted` 恢复，而不是伪装为仍在运行。
- 输出至少包含题目、正确答案、可核验解析、训练重点、知识卡来源和可选错题来源。
- 校验必须覆盖：数量、必填字段、题目去重、来源合法性、知识范围、所选知识卡覆盖和来源 revision。
- 任一输出或来源校验失败时，整批不保存；Agent 保留本次任务计划、来源选择和提示词，允许多轮修订后重试。
- 保存采用本地事务；一批题要么全部写入，要么全部不写入。

### 5.12 练习卡详情与追溯

- 每张练习卡展示题目、正确答案、解析、关联知识点和训练重点。
- 用户可以查看生成时引用的知识卡和错题，以及对应 revision。
- 练习卡保存生成时所用知识卡的完整不可变快照，包括标题、正文、类型和 revision。
- 来源后来被修改或删除时，已生成练习卡仍展示生成时快照，并明确标记“来源已变化”或“来源已删除”；当前版本与生成时版本不得混淆。
- 练习卡保留生成批次、模型/Provider、提示版本、难度、模板标识和有效自定义要求等元数据，供质量排查使用。

### 5.13 按批次浏览与清理

- 每次成功生成创建一个稳定且唯一的批次 ID；同批练习卡共享生成时间、来源摘要、难度、Provider、提示版本和提示词配置。
- 练习题库以生成批次为分页单位，默认打开最近批次，并允许切换到较早批次。
- 每个批次页显示批次时间、题目数量、知识卡/错题来源数量、难度和模板名称。
- 用户可以在当前批次内逐题勾选、全选/取消全选，并批量删除选中练习卡。
- 用户可以直接执行“删除本批”，一次删除该批次仍存在的全部练习卡。
- 批量删除和删除本批均需二次确认，并显示将删除的题目数量；取消确认不得产生写入。
- 删除使用本地事务。删除成功后同步更新批次数量；批次内没有剩余练习卡时，从分页导航中移除该批次。
- 删除练习卡及其来源快照不得删除或修改原始知识卡、错题和提示词模板。

## 6. 成功指标

### 6.1 首要指标

**知识细节覆盖合格率**

- **定义**：抽检的生成练习卡中，题目确实要求使用至少一项所选知识卡里的具体内容，而不是只提及同名知识点；同时来源声明可追溯到本次选择。
- **合格判定**：评审者能够指出被训练的知识细节，并确认完成该题需要理解或应用该细节。
- **当前基线**：🔵 **开放问题**：尚未建立测试集与基线。
- **建议目标**：🔶 **假设**：在至少 100 张、覆盖不同知识卡类型和难度的固定评测集上，合格率不低于 90%。
- **测量时点**：开发验收前一次；发布后 30 天使用真实本地样本再次抽检。真实内容抽检必须取得用户明确授权并脱敏。

### 6.2 次要指标

- **数学/事实正确率**：🔶 **假设**：题目可作答、答案正确、解析可核验的比例不低于 95%。
- **生成并保存成功率**：记录进入模型调用后的批次中，通过校验并完整写入的比例。🔵 **开放问题**：基线与目标待建立。
- **提示词模板复用率**：至少使用过一次模板的用户中，再次选择已有模板的比例。🔵 **开放问题**：目标待发布后建立。
- **来源追溯完整率**：已保存练习卡均含至少一条有效知识卡来源，目标 100%。
- **坏题清理完成率**：批量删除操作要么完整成功，要么不产生部分删除，目标 100%。
- **Agent 任务完成率**：用户在同一会话中发起的错题整理、知识卡生成或练习生成任务，最终达到成功或明确由用户放弃的比例。🔵 **开放问题**：需先建立任务状态基线。
- **多轮返工率**：因 Agent 遗忘已确认参数、取错来源或重复提问而产生的额外轮次占比；目标应随固定任务评测建立。
- **Token 利用率**：固定评测集中，最终被展示或批准的有效产物 token 占实际生成 token 的比例；失败、拒绝和重试消耗计入分母。

### 6.3 护栏指标

- 未选来源进入模型请求或练习卡来源关系的比例必须为 0。
- 来源 revision 冲突时写入过期结果的比例必须为 0。
- 生成练习不得修改用户原有知识卡或错题内容。
- 自定义提示导致固定规则、输出 Schema 或安全边界被绕过的比例必须为 0。
- 取消批量删除确认后发生误删的数量必须为 0。
- 未经批准执行创建、更新或删除的次数必须为 0。
- Agent 使用未选择、已过期或与当前任务无关来源的次数必须为 0。
- 页面绕过 Agent 直接调用 AI 生成接口的生产入口数量必须为 0。
- 对话压缩或恢复后丢失已确认任务参数、错误恢复 `running` 状态或执行失效审批的次数必须为 0。
- 浏览器模拟结果不能计入桌面端真实 AI 成功率。

### 6.4 最低埋点/本地统计需求

为计算指标，至少记录：会话/任务开始、任务类型、澄清轮次、计划确认、工具调用、审批结果、生成开始、生成成功、校验失败类型、保存成功、Provider、数量、来源数量、模板是否使用、批次 ID、恢复/中断和 token usage。默认不得记录知识卡正文、错题正文或完整自定义提示。

🔵 **开放问题**：本地优先产品采用纯本地统计、用户主动导出，还是匿名遥测？在确认隐私策略前不得上传事件。

### 6.5 Agent 评测与运行监控

V1 使用“代码断言 + 固定任务集 + 人工评测”的混合门禁：

| 层级 | 覆盖内容 | 最低门禁 |
|---|---|---|
| 代码断言 | Schema、来源 ID/revision、数量、状态迁移、审批、幂等、事务与取消 | 所有关键分支自动化测试通过 |
| 固定 Agent 任务集 | 错题整理、知识卡拆分/合并、练习批次、长对话、切页、重启、提示注入 | 每种任务至少包含成功、拒绝、冲突和恢复样本 |
| 生成质量集 | 知识细节覆盖、答案正确、解析可核验、难度和自定义提示遵循 | 至少 100 张练习卡；目标阈值按 6.1 确认 |
| 人工 trace 评测 | 是否重复提问、取错来源、忽略否决项、产生审批误导或无效工具循环 | 发布前逐条审核高风险样本；发布后定期抽检授权样本 |

开发诊断面板或可导出的本地运行记录至少能按任务查看：状态、步骤数、工具调用、审批、失败码、模型/Provider、首响应时间、总耗时、输入/输出 token 和最终交付 token。远程 Provider 的首响应时间只作为诊断指标，不设置脱离真实基线的统一硬 SLA。

以下情况视为阻断发布的严重告警：未经批准写入、使用未选来源、过期审批执行、来源 revision 绕过、取消后继续写入、重启后自动执行待审批动作、凭据进入模型或日志。

## 7. 用户故事与需求

### 7.1 Epic 假设

我们相信，让大学阶段学习者和成人自学者在一个统一浮动 Agent 中，通过多轮对话选择多张自由知识卡、补充个人错题和可复用提示词，再生成有来源的练习卡，可以提高知识细节覆盖合格率和复杂任务完成率，因为用户不再需要理解分散入口，也不再依赖通用题库或仅按知识点名称生成题目。我们将用固定任务集、生成质量评测和发布后授权样本验证这一假设。

### Story 1：创建灵活知识卡

作为个人学习者，我希望在同一知识点下创建多张自由知识卡，以便分别记录定义、推导、例子和个人理解。

**验收标准：**

- [ ] 用户可以填写标题和自由正文并保存知识卡。
- [ ] 正文支持项目现有的 Markdown/LaTeX 展示能力。
- [ ] 用户可以选择一个内置或自定义类型，也可以保留为“未分类”。
- [ ] 用户可以创建、重命名和删除自定义类型；类型名称在规范化后不得重复。
- [ ] 删除仍被知识卡使用的自定义类型前必须确认；确认后相关知识卡改为“未分类”，正文不受影响。
- [ ] 同一知识点下可以保存两张或更多知识卡，互不覆盖。
- [ ] 用户可以编辑和删除知识卡；编辑后 revision 增加。
- [ ] 不连接 AI 时，知识卡的创建、编辑、查看和删除仍可用。

### Story 2：迁移现有知识卡

作为现有用户，我希望升级后仍能看到原有知识卡，以免已经保存的学习内容丢失。

**验收标准：**

- [ ] 数据迁移为现有记录生成独立知识卡 ID 和初始 revision。
- [ ] 原有知识点路径、状态、内容、来源错题和时间信息得到保留。
- [ ] “核心方法”和“易错提醒”被转换为自由正文中的可读内容，不丢失文本。
- [ ] 迁移可以在已有数据库上重复检查，不产生重复知识卡。
- [ ] 迁移失败时不删除或覆盖原表数据，并返回可诊断错误。

### Story 3：选择练习生成依据

作为个人学习者，我希望明确选择要训练的知识卡，并按需附加错题，以便生成内容只基于我本次指定的材料。

**验收标准：**

- [ ] 至少选择一张知识卡后才可生成；错题可以不选。
- [ ] Agent 可以通过对话检索知识卡，也可以接收页面上下文胶囊中用户已勾选的知识卡。
- [ ] 用户可以在 Agent 中按知识点和知识卡类型缩小范围，并逐张选择或取消知识卡和错题。
- [ ] Agent 在计划中列出最终来源；批准后的请求只包含该清单中的 ID 与 revision。
- [ ] 取消勾选后，该来源不得出现在模型请求、输出来源或持久化关系中。
- [ ] 批准前的任务计划准确显示知识卡数、错题数、难度、数量和提示词配置。

### Story 4：保存并复用提示词模板

作为经常进行同类训练的用户，我希望保存自己的出题要求，以便以后不用重复输入。

**验收标准：**

- [ ] 用户可以创建带名称和内容的本地提示词模板。
- [ ] Agent 可以列出并选择模板；用户也可以通过有审批的工具创建、编辑和删除模板。
- [ ] 用户可以在模板之外填写一次性补充要求。
- [ ] 界面清楚区分“已保存模板”和“本次补充”。
- [ ] 模板删除不影响已生成练习卡及其生成元数据。
- [ ] 超出长度或包含无法执行要求时，界面给出可理解反馈并保留输入。

### Story 5：按知识细节生成练习卡

作为个人学习者，我希望 AI 根据所选知识细节生成新的可作答题目，以便检验自己能否迁移应用知识。

**验收标准：**

- [ ] 用户可以选择更简单、持平或更难，并设置 1–50 张练习卡。
- [ ] Agent 缺少知识卡、数量、难度或其他完成任务所需信息时，通过多轮对话补齐，不擅自使用未确认默认值。
- [ ] 每张输出包含非空题目、明确答案、可核验解析和训练重点。
- [ ] 每张输出至少引用一张本次所选知识卡。
- [ ] 一批输出覆盖本次全部所选知识卡；不能只覆盖其中一部分后宣称成功。
- [ ] 题目不得照抄来源；同批题目不得重复。
- [ ] 错题存在时，AI 可以利用真实错误点，但不得编造用户未提供的错误事实。
- [ ] 模板和本次补充只在不违反固定规则时生效。
- [ ] 生成数量下限等于所选知识卡数；减少数量或手工输入不得突破下限。

### Story 6：后台完成并自动保存

作为个人学习者，我希望开始生成后可以浏览应用的其他内容，以便不用停留等待。

**验收标准：**

- [ ] 生成中由浮动 Agent 展示当前阶段和“可以收起或离开本页”的说明。
- [ ] 收起 Agent或在应用内切换页面后任务继续；重新打开时恢复运行、失败或完成状态。
- [ ] 结构与来源校验全部通过后，整批练习卡自动写入本地题库。
- [ ] 保存采用事务；任一保存失败时整批不得出现部分落库。
- [ ] 成功后显示本批生成数量，并能打开每张练习卡。
- [ ] 关闭应用后不宣称任务仍在运行；重启时标记为 `interrupted`，并提供从安全检查点恢复或放弃的选择。

### Story 7：从失败中恢复

作为个人学习者，我希望生成失败后仍保留选择和要求，以便修正问题后直接重试。

**验收标准：**

- [ ] 区分 AI 未连接、模型调用失败、输出结构无效、覆盖不足、来源冲突和保存失败。
- [ ] 失败后在 Agent 任务中保留知识卡选择、错题选择、数量、难度、模板和单次补充。
- [ ] AI 不可用时，Agent 提供前往 AI 接入的路径；返回后恢复同一会话和任务。
- [ ] 来源 revision 已变化时，阻止保存并提示用户重新确认来源。
- [ ] 重试不会重复保存上一批成功结果。

### Story 8：查看生成依据

作为个人学习者，我希望知道一道练习在训练什么、依据了哪些内容，以便判断它是否值得练习。

**验收标准：**

- [ ] 练习卡详情展示训练重点和来源知识卡。
- [ ] 引用了错题时，同时展示来源错题和生成时 revision。
- [ ] 每条知识卡来源均可查看生成时保存的标题、正文、类型和 revision 快照。
- [ ] 可以打开仍存在的当前来源卡；来源已变化或删除时显示明确状态，并与生成时快照分开展示。
- [ ] 详情展示难度、生成批次和使用的提示词模板名称。
- [ ] 不在普通详情中暴露系统提示词、凭据或内部安全规则。

### Story 9：按批次浏览和删除练习卡

作为个人学习者，我希望按生成批次浏览和清理练习卡，以便快速移除一批不符合预期的题目。

**验收标准：**

- [ ] 每次成功生成的练习卡都关联同一个唯一批次 ID，不与其他生成混合。
- [ ] 练习题库按批次分页，默认显示最近批次，并可前后切换。
- [ ] 当前批次页显示生成时间、剩余题目数、来源摘要、难度和模板名称。
- [ ] 用户可以逐题勾选，并对当前批次中的选中项执行批量删除。
- [ ] 用户可以全选/取消全选当前批次，并执行“删除本批”。
- [ ] 删除前显示确认信息和准确数量；取消后所有练习卡保持不变。
- [ ] 批量删除采用事务，失败时不得只删除部分选中项。
- [ ] 删除后刷新卡片数和批次导航；空批次不再显示。
- [ ] 删除练习卡不会删除或修改来源知识卡、来源错题或提示词模板。
- [ ] 旧版没有批次 ID 的练习卡统一显示在“历史练习”兼容批次中，仍可勾选删除。

### Story 10：从任意页面进入统一 Agent

作为个人学习者，我希望所有 AI 功能都在同一个浮动 Agent 中完成，以便不用理解多套入口、状态和保存规则。

**验收标准：**

- [ ] 浮动 Agent 在所有主要页面可用，切换页面不会卸载当前会话。
- [ ] 原错题整理、知识卡生成和练习生成入口改为打开 Agent 的上下文入口，不再直接调用模型。
- [ ] 上下文入口预填任务意图并附加当前对象标识，但由用户发送或确认后才调用模型。
- [ ] 浮动按钮在收起时显示运行中、等待用户或等待审批状态。
- [ ] 手动编辑能力不依赖 Agent 或 AI Provider。
- [ ] 生产代码中不存在页面绕过 Agent 直接启动 AI 生成的入口。

### Story 11：通过多轮对话完成任务

作为个人学习者，我希望 Agent 记住我已经确认的要求并逐步完成复杂任务，以便不用一次写出完美提示词。

**验收标准：**

- [ ] Agent 将用户目标解析为明确任务类型、完成条件和当前状态。
- [ ] 缺少必要信息时每次只询问与完成任务直接相关的问题。
- [ ] 用户修改来源、数量、难度、模板或卡片拆分方式时，更新同一任务而不是创建重复任务。
- [ ] Agent 在执行前展示结构化任务计划，并允许继续讨论和修订。
- [ ] 新提案替代旧提案时，旧提案标记为 `superseded` 且不能再批准。
- [ ] 用户拒绝一次写操作后，仍可在同一会话中解释原因并要求修订。

### Story 12：让 Agent 生成和完善灵活知识卡

作为个人学习者，我希望 Agent 能根据错题、现有知识卡或我的说明创建和完善多张知识卡，以便把分散内容整理成可继续编辑的个人知识资料。

**验收标准：**

- [ ] Agent 可以读取用户明确选择的错题、知识卡、附件和对话说明。
- [ ] 用户可以要求创建一张或多张知识卡，以及拆分、合并、缩写、扩写或改写提案。
- [ ] 每张提案包含独立标题、自由正文、可选内置/自定义类型和知识点关系。
- [ ] 多张提案分别显示来源、warnings 和保存状态，不能合并成一张不可分割的审批。
- [ ] 用户可以逐张选择保存；未选或拒绝的提案不写入数据库。
- [ ] 更新已有知识卡时携带 `expectedRevision`；版本变化后必须重新读取并生成修订提案。
- [ ] AI 不得未经批准覆盖用户手写正文。

### Story 13：让 Agent 编排练习生成批次

作为个人学习者，我希望只告诉 Agent 自己想强化什么，再通过几轮对话确认批次，以便减少复杂表单操作。

**验收标准：**

- [ ] Agent 可以检索知识卡、可选错题和提示词模板，但只把与当前决策有关的结果加入上下文。
- [ ] Agent 明确展示每张所选知识卡至少对应一道练习及由此产生的数量下限。
- [ ] 批次计划显示最终来源、数量、难度、模板、单次补充、自动入库行为和预计影响。
- [ ] 用户批准批次计划后，Agent 才能启动生成与自动保存工具。
- [ ] 生成、校验、事务保存和批次元数据写入形成一个可观察任务。
- [ ] 完成后 Agent 返回批次链接、成功数量和可执行的继续生成、打开批次或清理建议。

### Story 14：持久化会话与任务检查点

作为个人学习者，我希望收起窗口、切换页面或重启应用后仍能找到任务，以便多轮工作不会因界面生命周期丢失。

**验收标准：**

- [ ] 对话、结构化任务参数、提案、审批、工具摘要和最终结果持久化到本地。
- [ ] 收起 Agent 或切换页面后重新打开，内容、滚动位置和待处理状态可恢复。
- [ ] 应用重启后，已完成、失败、等待用户和等待审批状态可恢复。
- [ ] 重启前仍在运行的任务恢复为 `interrupted`，不显示虚假进度。
- [ ] 用户可以从最近安全检查点恢复；恢复前重新校验来源与提案版本。
- [ ] 新对话不会静默丢弃活动任务或待审批项。

### Story 15：观察工具工作与控制 Agent

作为个人学习者，我希望看见 Agent 正在读取什么、准备写入什么并能停止任务，以便保持信任和控制。

**验收标准：**

- [ ] 时间线显示计划、工具开始/完成、来源数量、生成阶段、校验、审批和最终状态。
- [ ] 只读工具无需批准，但名称、目的和结果摘要可见。
- [ ] 创建、更新和删除工具执行前显示目标、数量、字段和级联影响。
- [ ] 运行中可以停止本轮；停止后不得继续写入或自动恢复。
- [ ] 批准、拒绝、过期和版本冲突是互斥且可恢复的明确状态。
- [ ] 同一会话同时最多一个活动运行，重复发送不会启动第二个运行。

### Story 16：保持有边界的 Agent 上下文

作为个人学习者，我希望 Agent 只读取完成当前任务所需的内容，以便减少误用资料、隐私暴露和无效生成。

**验收标准：**

- [ ] 页面上下文胶囊默认只包含路由、选择和对象 ID，不自动塞入整库正文。
- [ ] Agent 通过只读工具按需读取完整卡片，并记录每段上下文支持的当前决策。
- [ ] 未选择、无关或过期来源不会进入生成请求。
- [ ] 长对话压缩为结构化任务状态、摘要和最近相关消息；压缩前后已确认参数一致。
- [ ] 凭据、系统提示词、未授权文件和无关历史不会进入模型上下文或持久化聊天正文。
- [ ] 固定评测覆盖上下文错配、旧 revision、跨任务污染和提示注入。

### 7.2 数据与接口约束

以下为能力级约束，不是最终数据库设计：

- 知识卡必须从“知识点路径主键”迁移为独立 `id`，并具有 `revision`。
- 知识卡至少保存 `id`、标题、正文、可选 `typeId`、知识点关系、revision 与时间信息；自定义类型使用独立稳定 ID。
- 练习生成请求分别携带知识卡快照与可选错题快照；两类来源均包含 `id + revision`。
- 生成输出应包含 `question`、`correctAnswer`、`solution`、`trainingFocus`、`sourceKnowledgeCardIds` 和可选 `sourceMistakeCardIds`。
- 练习卡必须持久化两类来源关系、生成批次、有效提示配置，以及所用知识卡的完整不可变快照。
- 生成批次必须拥有独立 ID 和元数据；练习卡通过批次 ID 归组，删除批次时只级联删除其练习卡与来源快照。
- Agent 需要独立持久化 `conversation`、`message`、`task`、`checkpoint`、`proposal/artifact`、`toolCall`、`approval` 和 `run`；任务状态至少覆盖 `drafting`、`waiting_user`、`waiting_approval`、`running`、`failed`、`succeeded`、`cancelled`、`interrupted`。
- 页面向 Agent 传递类型化 `ContextCapsule`，只包含当前路由、选择、引用对象 ID/revision 和用户可见摘要；完整正文通过只读工具按需获取。
- 普通对话、错题提案、知识卡提案、练习批次计划和练习批次结果使用独立结果协议与校验器。
- 工具注册表必须明确输入 Schema、输出 Schema、副作用、审批要求、超时/取消和幂等键；Agent 不直接持有任意 SQL、文件系统或网络工具。
- 所有持久化更新继续使用 `expectedRevision`；审批记录绑定提案/计划版本，过期后不可执行。
- 前端、浏览器服务、Tauri command、Rust domain、AI Provider、Schema、SQLite migration 和测试 fixture 必须保持字段一致。

### 7.3 关键边界情况

- 知识卡只有图片或附件、没有可供模型读取的正文。
- 一张知识卡关联多个知识点，或一批来源跨多个知识点。
- 用户在生成期间编辑或删除来源知识卡/错题。
- 用户删除了正在使用的提示词模板。
- 模型返回题目数量不符、重复题目、无答案、错误来源或未覆盖全部知识卡。
- Provider 不支持结构化输出或返回超长内容。
- 自动保存成功但列表尚未刷新，导致用户重复点击生成。
- 批次中部分练习卡已被逐张删除，随后再执行“删除本批”。
- 旧版练习卡没有批次 ID，需要进入“历史练习”兼容批次。
- 旧版“一知识点一张卡”迁移后与用户新建卡重名。
- 用户从知识卡页面唤起 Agent 后切换到错题页面，原任务应继续使用已确认上下文，而不是静默改成新页面上下文。
- 同一会话中先整理错题、再生成知识卡、最后生成练习；每一步的产物和审批边界必须独立。
- 对话过长触发压缩，摘要遗漏数量、来源或用户否决项。
- 应用在模型请求、写入前、等待审批或保存完成后异常退出。
- 用户在等待审批时继续对话并要求修改计划，旧审批必须失效。
- Agent 收起时出现待审批或失败，浮动按钮必须给出可感知提醒。

## 8. 范围外

V1 不包含：

- 替代、仿真或保证达到考试真题质量；不提供押题承诺。
- 联网搜索、购买或导入官方真题题库。
- 完整在线作答、自动判分、掌握度分数、学习统计或间隔重复计划。
- 教师布置、班级、家长、协作、分享或多用户权限。
- 云同步、跨设备任务恢复和服务端后台队列。
- 多个用户可见子 Agent、递归 Agent 委派、并行任务队列或通用工作流平台。
- Agent 任意访问本地文件系统、执行 shell、直接写 SQL 或访问未注册外部网络。
- 页面继续保留绕过 Agent 的独立 AI 生成执行链路。
- 未经审批的自主写入，或把用户的一次聊天请求视为永久写入授权。
- 无限保留并在每轮发送完整会话、完整卡片库或全部历史任务。
- 允许用户编辑系统提示词、工具权限或输出 JSON Schema 的高级模式。
- 生成前逐题预览和逐题选择保留；V1 通过生成后的批量删除和“删除本批”清理结果。
- 独立于浮动 Agent 的全局任务队列/运维控制台，以及跨应用进程继续执行模型请求。
- 自动把 AI 练习结果写回或改写来源知识卡、错题。
- 完整知识图谱、向量检索或自动建立跨知识点关系。
- 浏览器预览中的真实 AI 调用；桌面端真实结果与浏览器模拟必须分开验收。

## 9. 依赖与风险

### 9.1 依赖

- **数据迁移**：现有 `knowledge_cards.key` 主键模型必须迁移为多卡 ID 模型，并保留旧数据。
- **领域模型**：TypeScript 与 Rust 需要统一新的知识卡、来源快照、生成输出和提示词模板结构。
- **AI 层**：Codex、DeepSeek 与兼容 API 路径需要使用同一业务 Schema 和覆盖校验规则。
- **存储层**：需要新增知识卡来源、练习卡到知识卡的来源关系、批次元数据和提示词模板存储。
- **Agent 工具层**：现有工具注册表需增加知识卡、提示词模板、练习计划/生成、批次查询与批量删除能力，并保留读写分级和审批。
- **Agent 状态层**：现有前端 reducer 与后端内存状态需升级为本地持久化的会话、任务、运行、提案、审批和检查点模型。
- **上下文桥接**：错题、知识卡、复习题和 AI 设置页需要统一产生类型化页面上下文胶囊，不能各自拼接任意 prompt。
- **结果协议**：普通对话、错题字段提案、知识卡提案、练习批次计划和批次结果需要独立 Schema、解析与渲染组件。
- **事件协议**：Agent 时间线需要覆盖等待用户、计划已更新、提案被替代、等待审批、后台生成、中断、恢复和批次完成。
- **渲染层**：自由正文必须复用现有数学内容渲染并处理不可信 Markdown。
- **质量评测**：需要建立覆盖不同卡片类型、难度和学科的固定测试集与人工判定准则。
- **AI 接入恢复**：生成失败后前往 AI 设置并返回原任务，需要稳定的导航和状态保存。

### 9.2 现有能力迁移账本

| 能力 | 当前实现 | 目标归属 | 迁移完成标准 |
|---|---|---|---|
| 错题 AI 整理 | 编辑器/详情页直接调用整理服务 | Agent 的错题提案工具 | 页面只负责打开 Agent；逐字段确认、revision 和草稿保护均保留 |
| AI 知识卡生成 | 知识卡页面启动固定结构生成并自动保存草稿 | Agent 的多知识卡提案与保存工具 | 支持自由正文、多卡拆分/合并、逐卡确认和版本冲突 |
| AI 练习生成 | 复习题页面直接启动后台生成 | Agent 的批次计划与生成工具 | 计划审批后自动入库，覆盖、批次、来源快照和删除能力完整 |
| 页面生成状态 | 多个模块级/组件级 store | Agent 持久化任务与时间线 | 收起、跨页、失败和重启恢复语义一致 |
| 对话历史 | 前端内存中的最近消息字符串 | 结构化会话、任务状态、摘要和最近消息 | 多轮参数不丢失，不把完整历史重复塞入上下文 |
| Agent 工具 | 6 个错题/知识点工具 | 分域、类型化工具注册表 | 每个工具有 Schema、副作用、审批、取消、幂等与测试 |
| 写操作审批 | 单卡创建/更新/删除的内存审批 | 所有内容写入与删除的持久化审批 | 过期/替代/冲突不可执行，重启后重新校验 |
| 运行反馈 | 状态、工具、审批和完成事件 | 完整任务状态机 | 时间线与浮动按钮均能表达等待用户、运行、中断、失败和完成 |

旧页面的直接 AI 链路只有在对应 Agent 端到端旅程通过后才能删除。迁移期间不得长期保留两条生产写路径；短期特性开关必须明确唯一权威路径，并在迁移结束后移除。

### 9.3 建议交付顺序

1. **Agent 基础状态**：先完成会话、任务、检查点、提案和审批持久化，以及浮动按钮状态提醒。
2. **灵活知识卡模型**：完成多卡数据迁移、自由正文、类型与 revision，再开放 Agent 知识卡工具。
3. **上下文与工具合约**：实现页面上下文胶囊、按需检索、独立结果协议和工具级测试。
4. **练习批次 Agent 化**：接入计划审批、知识驱动生成、事务保存、来源快照和批次清理。
5. **错题整理 Agent 化**：迁移现有逐字段提案并删除页面直连模型入口。
6. **质量门禁**：运行固定任务集、生成质量评测、上下文/提示注入测试、审批与恢复旅程，再移除旧链路。

### 9.4 风险与缓解

| 风险 | 类型 | 缓解措施 |
|---|---|---|
| 题目只提到知识点名称，没有真正训练所选细节 | 价值 | 输出训练重点与知识卡来源；建立覆盖判定集；覆盖不足整批失败 |
| AI 给出错误答案或不可解题目 | 价值/可用性 | 结构校验之外增加固定样本人工评测；详情始终展示答案和解析来源信息 |
| 自由知识卡内容质量差，无法出题 | 可用性 | 生成前检查正文是否足够；提示用户补充定义、条件或例子；保留原输入 |
| 多张卡让知识空间变得难以管理 | 可用性 | 提供知识点、类型和文本筛选；不强制模板；空类型保持可见 |
| 自定义提示注入或覆盖系统规则 | 可行性/安全 | 固定规则与用户要求分层；把模板作为不可信数据；服务端校验最终输出 |
| 单一 Agent 入口让原本明显的页面操作变得难找 | 可用性 | 保留页面上下文入口；打开 Agent 后展示预填目标、当前来源和下一步 |
| Agent 为完成任务加载整库内容，造成上下文噪声和隐私风险 | 可行性/信任 | 上下文清单分层；只传 ID；按需读取；限制结果数；记录检索用途 |
| 多轮对话遗忘已确认条件或混入上一个任务 | 可用性/可行性 | 使用结构化任务状态与检查点；新目标触发任务切换确认；固定上下文错配评测 |
| 为所有任务扩展一个万能 Schema，导致解析脆弱 | 可行性 | 普通对话、错题、知识卡和练习批次使用独立协议与校验器 |
| 每个写步骤都审批造成审批疲劳 | 可用性 | 只读与生成提案不审批；在真正写入边界集中审批；练习批次只审批一次计划 |
| 应用重启后内存 run/approval 丢失或被误执行 | 可行性/安全 | 持久化状态；运行恢复为 interrupted；审批执行前重新校验版本和影响 |
| Agent 成为唯一入口后出现单点故障 | 可行性 | 手动编辑始终可用；Agent 失败保留任务与输入；各工具可独立测试和重试 |
| 多轮与工具调用导致 token/延迟上升 | 可持续性 | 轻量 ChatReply；上下文摘要；按需检索；独立 Schema；记录实际 token 利用率 |
| 不同 Provider 的结构化输出稳定性不同 | 可行性 | 使用统一 Schema、解析器和 Provider 合约测试；错误分类后允许重试 |
| 数据迁移覆盖或丢失现有知识卡 | 可行性 | 迁移前后计数与内容校验；保留旧数据直至迁移成功；加入回归测试 |
| 自动保存坏题污染练习题库 | 价值/可用性 | 提高保存前校验；按批次分页；支持勾选批量删除和删除本批 |
| 指标需要读取私人学习内容 | 可行性/信任 | 默认只存本地事件；正文抽检必须显式授权并脱敏 |
| 功能范围扩展成完整学习管理系统 | 可行性/可持续性 | 严格遵守范围外清单；V1 只完成知识记录、生成与来源追溯 |

## PRD 自评

### 最强部分

**Agent 目标架构、上下文边界与迁移路径**。方案明确使用一个 Agent 和分域工具，而非多个子 Agent或万能 Schema；页面入口、任务状态、审批、恢复和现有生成能力的迁移关系均可追踪。

### 最弱部分

**用户证据、指标基线和关键审批交互**。当前结论主要来自产品方向确认和代码/文档盘点，没有访谈、真实使用行为或覆盖率基线；页面唤起、批次计划授权和多卡提案批准仍需交互验证。

### 最高风险假设

| 假设 | 风险 | 建议验证 |
|---|---|---|
| 用户愿意持续创建细粒度知识卡 | 没有足够输入，知识驱动生成价值不足 | 访谈 5 名大学/成人学习者，并观察其现有笔记 |
| 90% 覆盖合格率足以建立信任 | 阈值过低会产生坏题，过高可能不可达 | 建立 100 张固定评测集并比较 Provider |
| 按批次分页和删除足以控制自动入库污染 | 低质量题仍可能在用户清理前干扰题库 | 测试不同批次数量下的定位、勾选和删除效率 |
| 用户愿意在浮动 Agent 中完成原本页面内的 AI 操作 | 统一入口可能增加简单任务步骤 | 用错题整理、知识卡生成、练习生成三个原型旅程做可用性测试 |
| 结构化任务摘要足以支撑长时间多轮工作 | 摘要遗漏会导致取错来源或重复询问 | 建立长对话、切页、重启和提案替代的固定 Agent 评测集 |
| 一次批次计划审批能让用户理解自动入库影响 | 用户可能误以为只是生成预览 | 审批卡明确数量、来源和自动保存；测试复述理解度 |

### 推荐下一步

在进入生产代码前，先制作浮动 Agent 的三个可交互旅程原型：错题整理、生成多张灵活知识卡、从知识卡生成练习批次。用它验证页面唤起、多轮澄清、任务计划、逐卡/批次审批、收起后提醒和失败恢复；同时建立至少 100 张练习卡的质量评测集。原型结论与评测阈值应先回写本 PRD，再冻结 Agent 工具和数据合约。
